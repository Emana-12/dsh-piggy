# Codex 小猪联动插件设计

日期：2026-10-12  
状态：设计稿，已获用户确认（2026-10-12）
来源：`dsh-piggy` v0.36.0（GitHub `CLICGGER-TYPES/dsh-piggy`）

## 1. 目标

把现有小猪养成玩法接入 Codex，使用户能在 Codex 对话中查看并操作养成系统，同时让 Codex 和桌面悬浮小猪操作同一只猪、同一份状态。保留原桌面版作为常驻视觉宠物和唯一存档所有者。

完整移植范围覆盖现有核心养成、物品与商店、学习、工作、旅行、钓鱼、日记、图鉴、成就、形态与皮肤，以及菜园、矿洞、扭蛋、盲盒四个现有扩展。原有规则、数值、文案、成就条件和图片素材保持一致；只有 Codex 的入口与屏幕布局按宿主适配。

## 2. 用户可见行为

- 用户可以在 Codex 中用自然语言查看小猪状态，并执行喂食、洗澡、玩耍、上学、打工、旅行、钓鱼、购物、换装、查看图鉴/成就/日记等原有操作。
- Codex 里触发的操作会立即更新桌面小猪的状态、形态、表情、动作和气泡；用户在桌面宠物面板上的操作也会立即反映到 Codex。
- 在 Codex 设置完成联动后，Codex 工作事件按原养成规则计入小猪的工作成长。只传递必要的事件类别和成功/失败状态，不记录或上传用户提示词、源代码、命令正文或工具参数。
- 猪的成长、健康、钱包、背包、活动、扩展状态等均从桌面版当前存档读取。两个入口不能分别创建互相冲突的存档。
- 菜园、矿洞、扭蛋和盲盒在 Codex 中保留原有开关、进度、操作和结果，并与桌面版共享状态。

## 3. 架构

### 3.1 桌面版是状态所有者

复用桌面版 Electron 主进程和现有 `store.js` / `packages/pet-core/` 规则作为唯一状态所有者。新增仅限本机 IPC 的联动桥（Windows 命名管道；macOS/Linux Unix domain socket）。IPC 服务由桌面版主进程随宠物启动，并在退出时关闭。

所有写操作由桌面版进程串行执行，复用现有存档节流、迁移、日志和 `dispose()` 收尾流程。Codex 插件不直接读写 `state.json`，避免多进程覆盖与损坏。

### 3.2 Codex 插件

新增一个 Codex 本地插件包，包含插件清单、使用技能、MCP stdio 服务器和联动钩子。MCP 服务器只调用本机 IPC，并映射到现有 store API；每个工具使用明确输入结构，返回状态快照、动作结果和可读错误。

MCP 工具至少覆盖：连接/绑定、读取状态、照顾、交互、学习/工作/旅行/钓鱼、背包/商店/换装、图鉴/成就/日记、签到/番茄钟，以及四个扩展的状态与动作。危险或不可逆的操作（重置存档、删除扩展、覆盖皮肤等）保留明确确认步骤。

Codex 中以插件工具和技能作为完整操作入口。若当前 Codex 宿主支持 MCP Apps 界面，则提供游戏面板；若界面资源不可用，所有功能仍可通过 Codex 工具和对话完成，不依赖 MCP Apps 才能养成。

### 3.3 桌面小猪联动

绑定流程只指向一个桌面宠物实例。桌面版启动 IPC 后，Codex 插件完成配对并保存稳定的 `pigId`；之后每个写操作都携带此 ID，桌面版校验后执行。连接丢失时，Codex 显示“桌面小猪未运行/未连接”，不创建另一只猪，也不静默写入副本存档。

桌面版收到成功的 Codex 操作后，沿用当前状态刷新和猪窗口表现机制，更新立绘、动作和气泡。桌面面板操作由同一个 store 更新；IPC 订阅状态变更并向 Codex 返回最新快照。

### 3.4 Codex 工作事件

安装在本机 Codex 的钩子将 `PostToolUse`、`Stop`、`SessionStart` 等已支持事件映射为现有养成事件。钩子只发送白名单事件类别、成败标志、会话内去重标识及时间；不解析 transcript，不发送 prompt、代码、命令或工具参数。桥接/桌面端不可用时钩子快速返回，不能阻断 Codex 原工作。按现有静默和免打扰规则控制小猪主动气泡。

## 4. 配对、存档与失败处理

- 配对以桌面版当前存档中的 `pigId` 为准；Codex 插件不复制存档。
- 若存档尚无稳定 ID，首次启动时新增默认 ID 字段，不升级存档版本；若将来需改变已有字段结构，遵守现有迁移与备份机制。
- 若桌面版未启动、IPC 不可达或绑定 ID 不一致，查询和写操作均返回可诊断错误及“启动桌面小猪/重新配对”的步骤。
- MCP 工具对输入再次做类型、范围、枚举与操作白名单校验；桌面主进程仍是最终校验者。
- 请求使用短超时和请求 ID 去重；超时后允许查询状态确认结果，不能盲目重复消费物品或重复结算。
- 联动日志只写事件类别、请求 ID、结果码和异常摘要，不保存会话内容。桌面端原有导出日志机制包含联动诊断信息。

## 5. 安装与范围

目标是本机 Codex Desktop/CLI 插件与本机桌面宠物共同工作。插件安装说明会要求桌面版处于运行状态，并提供配对步骤。公开目录发布和跨设备/云端共享不属于本次；本机联动需要可执行的本地 stdio MCP 与 IPC 权限。

桌面版 UI、悬浮窗口、托盘、拖动、更新机制和现有 DSH 插件维持现状。DSH 网页插件原有独立存档不自动合并；Codex 绑定桌面版当前存档。

## 6. 验收标准

1. Codex 插件清单、技能和 MCP 工具能在本机 Codex 安装并发现。
2. Codex 查询到的身份、成长、健康、钱包、背包、活动与桌面面板完全一致。
3. 在 Codex 喂食/照顾/操作后，桌面小猪及时展示对应状态/动作；在桌面面板操作后，Codex 随后的查询返回新状态。
4. Codex 工作事件按核心养成规则处理，重复事件不会重复计数；钩子故障不会影响 Codex 工具执行。
5. 原有四个扩展可以从 Codex 查询和操作，桌面端看到相同扩展进度。
6. 桌面端关闭或配对不一致时，不会产生第二份存档；Codex 会明确报告无法联动。
7. 操作覆盖原有玩法，不改变原数值和文案；规则层现有测试继续通过，新增 IPC/MCP/配对与事件映射测试覆盖跨进程行为。
8. Windows 为首要验收环境；macOS/Linux IPC 路径按现有桌面版支持范围验证。

## 7. 实施顺序

1. 先实现桌面端 IPC 只读状态、配对 ID 和状态变更订阅，并在真实 Codex MCP stdio 客户端验证连接生命周期。
2. 加入受控动作映射，优先覆盖状态查询、照顾与日常核心玩法，再逐项覆盖复杂子系统和扩展。
3. 添加 Codex 钩子事件映射和去重；确认不会读取或记录会话内容。
4. 增加插件安装、配对、恢复连接说明；验证 Codex UI 能力后决定是否随插件提供 MCP Apps 面板。
5. 运行规则、桥接、迁移和端到端联动验证，最后在桌面端和 Codex 中逐项验收。
